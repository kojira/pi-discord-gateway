# Issue #14: Persistent Gateway → Pi RPC

Status: latest user-approved SMALL persistent design; replaces the lease/guardian proposal in its entirety. Implementation and isolated validation in this branch only. No deployment/main merge, installed edits, Pi/subagents edits, or operational data changes.

## Source check and cause

Base Gateway `b425230`: `invoke.ts` closes stdin at `agent_settled`; Pi EOF disposes runtime; pi-subagents shutdown cancels asynchronous workflows. Parent idle is not evidence that children or delayed result delivery have finished. Current Pi RPC supports multiple `prompt` commands and unsolicited events on the same connection. `prompt` with `streamingBehavior: followUp` starts when idle and queues when streaming; `steer` alone does not wake an idle parent. Pi's existing `sendCustomMessage(..., {triggerTurn:true})` starts an idle parent. No new Pi API is needed. Reviewed the full Pi RPC documentation and corresponding prompt/custom-message paths.

## Concrete implementation contract

- Opt in with `PI_RPC_PERSISTENT=true` (default false for existing installations whose concurrency/resource assumptions remain request-scoped). Disabled mode retains request-scoped EOF, legacy settlement and tests. Enabling uses the existing RPC protocol, not managed-lifetime flags or capability negotiation.
- One connection per channel folder, owned in memory by Gateway. No pool, idle timer, eviction, lease, child counting, process guardian, DB migration or resume protocol. Unknown child activity is never grounds for automatic close.
- Request lifetime ends at the existing settlement boundary after its input has been observed and queued delivery/steering-consumption callbacks drained. This releases queue row, typing and the admission slot, but leaves stdin, output subscription and supervisor watcher open. An unsolicited settlement cannot finish a newly queued but unconsumed user request.
- RPC events lack request IDs. Before each prompt, require `get_state.pendingMessageCount === 0`; reject without sending/closing/replay otherwise. After submission, the first user-role `message_start` is consumption (including transformed inputs); custom-role child notifications do not count. The snapshot is not atomic. Concurrent extension `sendUserMessage` injections are unsupported; extensions must use custom messages for asynchronous parent notifications. Source search found subagents parent completion uses `sendMessage`; its `sendUserMessage` use is in the child steer-inbox runtime. This bounded correlation choice was approved by supervisor during source-check.
- Subsequent requests reuse the original process with `prompt/followUp`; active-request steering keeps existing native steering behavior. Request callbacks/signals are detached at settlement. Independent connection callbacks deliver later assistant messages, work summaries, errors, trace and supervisor requests without touching a completed queue row. Delivery ordering and byte bounds remain in effect. No synthetic user input or tool replay.
- `MAX_CONCURRENCY` remains a limit on Gateway-dispatched user requests, NOT resident connections or autonomous child-triggered parent runs. One process may remain per visited channel. Strict global autonomous model scheduling is explicitly out of scope.
- Launch identity (binary, extra flags, model, thinking, cwd, session directory) is fixed while connected. Changed settings reject the next request with an explicit `/stop` instruction, rather than killing unknown work or silently using stale settings. `/new` refuses while a resident connection remains, instructing `/stop` first. No automatic session rotation under a live writer.
- Supervisor files already contain `orchestratorSessionId`; persistent watchers filter on the connection's `get_state` session ID, avoiding cross-channel delivery. No extension changes or filesystem-root relocation. Legacy watcher behavior remains unchanged.
- Stop addresses resident connections even when no request is active. Shutdown stops all resident connections after request drain, including idle ones, and aborts connection delivery signals before resource teardown. Stop sends clear_queue/abort and EOF, with bounded TERM/KILL escalation targeting the direct Pi process only. Reports say stop requested, not descendant cancellation confirmed. Detached descendants/external jobs may survive; no arbitrary-descendant guarantee, ownership probing or replay. Crashes fail an active request or report a late connection error; no automatic replay. A later new user request can start a new process only after the prior connection is closed.
- Session status reuses an existing connection for `get_session_stats`, rather than spawning another session-owning Pi against the same file.
- Explicit completion (`work_contract`/finish_work summaries and errors), modern settlement and legacy compaction/retry behavior remain. Physical idle is not workflow completion.

## Validation and boundaries

Focused subprocess regressions: parent idle then delayed child output without user input/EOF; next request same PID; stale request signal detached; independent late delivery and supervisor routing; unrelated settlement cannot complete queued request; stop/shutdown idle process; settings mismatch; legacy off and existing completion/compaction tests. Queue tests cover completed-row isolation and shutdown. Real isolated Pi RPC with a deterministic local provider and delayed custom-message extension if feasible (no paid API, production settings or sessions). Measure idle direct-process RSS and distinguish baseline from loaded extensions/children/context, which are not inferred from the baseline.

## Checked implementation and measurement (2026-09-12)

- Gateway-only implementation, opt-in default off. No lease/guardian source remains in the Gateway diff; other repositories and installed packages were not edited.
- Persistent assistant/work-summary delivery shares the bounded ordered delivery chain. Request summary is delivered before request resolution; later custom-result output cannot be hidden by an older summary. Accepted but unobserved steering rows fail rather than replay into a still-live Pi. This is failure/uncertainty, not proof the input never ran.
- Persistent commands have a 30-second response deadline (not an idle timeout or workflow runtime limit). A pending user queue rejects admission without stopping Pi. Late transport/output errors report interruption even after the original row finished. Shutdown aborts a Gateway-owned delivery signal as well as each connection signal.
- `pnpm test`: **28 files / 172 tests passed**. Includes 7 focused persistent process cases, queue delivery after row completion, and real isolated Pi RPC. Existing off-mode explicit-completion/compaction, steering, shutdown and safety tests remain passing. `pnpm build`, `pnpm lint`, `pnpm format:check`, `git diff --check` passed. No staged files.
- Real integration used read-only installed **Pi 0.74.2**, isolated HOME/cwd/agent-dir/session-dir, explicit local deterministic provider/extension, no inherited auth or operational extensions, no network or paid API. Two actual Node children exited 0, a delayed **custom** message woke the original idle parent, live status used that connection, the next request used the same PID, and shutdown removed the direct Pi process. This exercises the older Pi legacy settlement path; modern `agent_settled` / explicit-work-contract behavior is covered by subprocess regressions, not by a paid model run.
- macOS arm64 / Node v22.23.2 bare idle direct Pi after `get_state`: **161,088 KiB (157.31 MiB)** RSS in three 1-second-spaced samples. A separate fixture run after three provider calls and both child exits: **173,872 KiB (169.80 MiB)** direct Pi RSS. Neither includes production pi-subagents/other extensions, large session histories, active children, Gateway RSS, nor OS shared-page accounting adjustments. These are measurements, not a production capacity guarantee.
- Reproduction/evidence outside source: archive directory above contains `measure-idle.mjs`, `idle-rss-report.json`, `real-rpc-report.json`, plus validation logs. Run the source integration with `pnpm exec vitest run test/rpc-persistent.integration.test.ts`; optional `PI_RPC_TEST_CLI` selects another read-only Pi CLI, `PI_RPC_TEST_REPORT` writes its measurement JSON.

Residual boundaries: no strict autonomous global concurrency bound, no arbitrary detached-descendant/external-job stop guarantee, no durable Discord outbox/restart resume, no support for concurrent extension-injected user-role prompts, and no deployed Discord/provider acceptance. Independent review is owned by the supervising session; local checks do not substitute for it.
