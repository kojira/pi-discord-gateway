# D-000001 — 設計IDの運用とCIチェック（提案）

状態: **設計中・未承認**。この文書だけで運用開始、コード作成、CIの有効化を許可しない。`D-000001` はこの提案のIDであり、全リポジトリで採番する仕組みはまだない。

## 何を共有するか

リポジトリをまたいで使う **Piのスキル（作業手順）** と **再利用可能なCIチェッカー** を一つずつ用意する。各対象リポジトリでは、CIから共通チェッカーを呼び出し、そのリポジトリの設計文書のパスとPR情報を渡すだけにする。CIを設定していないリポジトリは**保護対象ではない**。Piの実行時拡張、台帳、会話記録の監査、ダイジェストの照合、常時監視は作らない。

親エージェントはオーナーの明示的な指示を確認し、子エージェントへの依頼を管理する。**実装は子エージェントだけが行う**。スキルは人とエージェントの作業手順であり、子の起動を技術的に止めるものではない。

## オーナーが見る流れ

1. 設計段階でID入りのMarkdown設計文書を書き、コミットする。小さな変更なら短い文書でよい。オーナーには要約だけでなく実際の文書を見せ、**その設計への明示的な承認**を受ける。文脈上その設計の承認であることが明らかな「ok」も含む。必要な確認を済ませたら、その承認をもって直ちにIMPLEMENTへ進む。別途、実装開始指示は求めない。過去の承認やエージェントの判断だけで段階を進めない。
2. 子に依頼する前に、親はID、段階、依頼文を指示ログ（例: Issueのコメントやコミット済み文書）に記録する。設計調査・レビュー・追加依頼も同様に記録する。実装の子への依頼にはIDを入れ、ログと設計をひも付ける。
3. 実装PRには、ID、設計文書のパスとその文書を書いたコミットSHA、最初の実装コミットSHA、同じIDの指示ログへの参照、設計承認（実装開始を兼ねる）のオーナー指示への参照を一つ、短い証拠欄として載せる。レビュアーは参照先の内容と文脈を読む。リンクがあるだけで承認済みとはみなさない。
4. 実装開始後に設計の変更が必要なら実装を止め、オーナーから**設計段階へ戻す指示**を受ける。設計を別の設計用PRで変更・コミットし、新たな設計承認を受けて必要な確認を済ませたら、新しい実装PRに進む。実装PRの中で設計文書を後から書き換えない。完了にもオーナーの明示的な指示が必要だが、CIが完了を判定するわけではない。

## CIで赤にする条件

共通チェッカーは、設定済みリポジトリの実装PRで、PRのbase/head、証拠欄、設計文書のパスを受け取る。各リポジトリのCIは検査に必要なコミットとPR情報を取得する。

- 証拠欄にID、パス、コミットSHA、指示ログへの参照と設計承認（実装開始を兼ねる）のオーナー指示への形式の整った参照一つがない、または設計コミット時点のMarkdown文書に同じIDがなく、そのコミットで文書が書かれていない場合は赤にする。CIが確認するのは参照の**形式**までであり、指示の中身や本人性は人が確認する。
- 最初の実装コミットには `Design-Phase: IMPLEMENT` というコミットトレーラーを一つ付け、証拠欄にそのSHAを書く。設計コミットはこの実装コミットの**厳密な祖先**でなければならない。マーカーの欠落・重複、SHAの不一致、実装コミットに設計文書以外の変更がない場合は赤にする。
- PRのbaseからheadまでの直線的なコミット順を調べ、最初の実装コミット**以降**に該当する設計文書を変更したら赤にする。直線的でない履歴や、必要な履歴を取得できず順序を確かめられない場合も赤にする。設計コミットが既にbase側にあってもよい。設計だけのPRには実装マーカーを付けず、実装の検査を通過したとは扱わない。

これはPR内の順序と文書差分を調べる小さな検査であり、全履歴の監査ではない。単純なコミット順とトレーラーで「実装コミット以降の設計変更」を拒否できる。設計段階へ戻る必要があれば、マーカーを後ろに動かして赤を消すのではなく、オーナーの指示に従って別の設計用PRを作る。rebaseやsquashでSHAが変われば証拠欄を更新する。

**CIが赤ならマージしない。** エラーには不足する参照、順序違反、変更された設計文書を示し、証拠の補完、コミットの整理、または設計段階への差し戻しを案内する。CIはローカル作業や子の起動を止められず、ログが子の起動**前**に書かれたこと、マーカーより前に実装作業が始まっていないこと、参照先が本当にオーナーの指示であることも証明できない。PR外の作業や未設定のリポジトリにも効かない。これらは人がレビューする。

## 未決定

この簡素な契約、PRの証拠欄・トレーラーの形式、CIを導入する対象リポジトリにはオーナーの承認が必要。承認前にスキルやチェッカーを実装・有効化しない。
